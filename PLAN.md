# Translitra — Chrome-расширение транслитератор (кириллица ⇄ латиница)

Дата: 2026-10-16

## 1. Название

Рекомендация: **Translitra** (запасные: Translitify, Translito).

Проверка (поиск по индексам Chrome Web Store, chrome-stats, chromeboard, extscope):

| Вариант        | Статус                                                        |
|----------------|---------------------------------------------------------------|
| Translitra     | не найдено ни одного расширения — свободно                    |
| Translitify    | не найдено — свободно                                         |
| Translito      | не найдено — свободно                                         |
| Kirilat        | не найдено — свободно (но плохо читается на англ.)            |
| Translit       | ЗАНЯТО минимум 3 раза (Mark Stein, mdfgdlf…, eflchmh…)        |
| Transliterator | ЗАНЯТО («Transliterator - EdinB», «Russian Transliterator»)   |
| Azbuka         | ЗАНЯТО (ближайший конкурент: Cyr⇄Lat через контекстное меню)  |
| Cyrillatin     | ЗАНЯТО                                                        |
| Latinka/Latynka| ЗАНЯТО (украинские расширения)                                |

Перед регистрацией обязательно вбить название в поиск самого магазина
(chromewebstore.google.com/search/Translitra) — автоматически его открыть не удалось
(Google ставит consent-редирект). Названия в CWS не уникальны, но дубликат известного
имени даёт отказ по политике «misleading / impersonation».

Чем отличаемся от конкурентов (у всех — только контекстное меню или только попап):
- всплывающая подсказка сразу при выделении;
- авто-определение направления;
- несколько стандартов транслита (ГОСТ 7.79-2000 Б, загранпаспорт/ICAO, BGN/PCGN, «народный»);
- отдельное окно-конвертер.

## 2. Функционал (MVP)

1. **Выделил — всплыл перевод.** Content script ловит `selectionchange`/`mouseup`,
   показывает маленький тултип (Shadow DOM) рядом с выделением: транслит + кнопка
   «копировать». Направление определяется автоматически по доле кириллицы.
2. **Иконка расширения (popup).** При открытии берёт текущее выделение активной вкладки
   (`chrome.scripting.executeScript` → `getSelection().toString()`), показывает исходник
   и результат, поле можно редактировать, результат пересчитывается на лету.
3. **Отдельное окно.** Кнопка «Открыть в окне» в popup → `chrome.windows.create({type:'popup'})`
   на ту же страницу-конвертер; состояние хранится в `chrome.storage.session`.
4. Контекстное меню «Транслитерировать выделенное» (дублирует п.1, нужен для случаев
   когда тултип отключён).
5. Горячая клавиша (`commands`), по умолчанию Alt+Shift+T — открыть окно с выделением.
6. Настройки: стандарт транслита, вкл/выкл тултип, задержка показа, тема.

Не в MVP (потом): замена текста прямо на странице / в полях ввода, Firefox-сборка,
пользовательские таблицы соответствий.

## 3. Архитектура (Manifest V3)

```
transliterator/
├─ wxt.config.ts
├─ package.json
├─ src/
│  ├─ core/                      # чистый TS, без browser API — покрыт тестами
│  │  ├─ tables/
│  │  │  ├─ gost-7.79-2000-b.ts
│  │  │  ├─ icao-passport.ts
│  │  │  ├─ bgn-pcgn.ts
│  │  │  └─ popular.ts            # «народный» (sh, ch, yu, ya, ' , '')
│  │  ├─ detect.ts               # направление: cyr→lat / lat→cyr / mixed
│  │  ├─ toLatin.ts              # посимвольно + контекстные правила (е/ё в начале слова и т.п.)
│  │  ├─ toCyrillic.ts           # токенизатор longest-match: shch > sch > sh > s
│  │  ├─ casing.ts               # сохранение регистра: Щука→Shchuka, ЩУКА→SHCHUKA
│  │  └─ index.ts                # transliterate(text, {standard, direction?})
│  ├─ entrypoints/
│  │  ├─ background.ts           # service worker: contextMenus, commands, открытие окна
│  │  ├─ content.ts              # тултип при выделении (Shadow DOM, свои стили)
│  │  ├─ popup/   (index.html, main.ts)
│  │  ├─ window/  (index.html, main.ts)   # отдельное окно-конвертер
│  │  └─ options/ (index.html, main.ts)
│  ├─ shared/
│  │  ├─ settings.ts             # chrome.storage.sync обёртка + дефолты
│  │  └─ messages.ts             # типизированные сообщения runtime.sendMessage
│  └─ assets/icons/ 16,32,48,128.png
├─ tests/core/*.test.ts          # vitest
└─ store/                        # ассеты для магазина: скриншоты, промо, описание, privacy.md
```

Стек: **WXT** (Vite + TS, авто-manifest, HMR, `wxt zip`, позже Firefox одной командой),
**Vitest** для core, без UI-фреймворка (ванильный TS + немного CSS) — popup крошечный.
Альтернатива: CRXJS + Vite. Не брать: Webpack-бойлерплейты и MV2-примеры из старых статей.

Permissions (минимум — это влияет на скорость ревью):
- `contextMenus`, `storage`, `activeTab`, `scripting`
- `content_scripts.matches: ["<all_urls>"]` — нужен для тултипа при выделении.
  Это «широкие host-permissions», ревью дольше и в Privacy-вкладке нужно внятное
  обоснование: «читает только выделенный пользователем текст, ничего не отправляет».
- Никаких `tabs`, `webRequest`, remote-кода (MV3 его запрещает). Всё офлайн.

## 4. Ключевые решения в ядре транслитерации

- Таблицы — массивы правил `[cyr, lat]`, многобуквенные латинские сочетания отдельно.
- **Кириллица→латиница**: простая замена с учётом контекста (ё, е после гласных/ь/ъ в
  ICAO не различаются; в ГОСТ Б: ц→cz/c перед i,e,y,j; ъ→``, ь→`, й→j, э→e`).
- **Латиница→кириллица**: главная сложность — неоднозначность. Жадный longest-match по
  отсортированному списку (shch, sch, zh, kh, ts, ch, sh, yo, yu, ya, ye, …, ', '').
  Для «народного» стандарта принять соглашения: `y` в конце слова → й, `j` → й, `e` → е,
  `yo` → ё. Честно показывать в UI, что обратный транслит неточен.
- Регистр: если токен в источнике весь верхний и слово ≥2 букв верхнего → результат upper;
  иначе Title-case.
- Небуквенные символы, цифры, латиницу внутри кириллицы (URL, бренды) — не трогать.
- Производительность: тултип только для выделения ≤ 2000 символов; окно — без лимита.

## 5. Пошаговый план (≈ 5–7 вечеров)

| Шаг | Что делаем | Готово, когда |
|-----|------------|---------------|
| 0 | `pnpm dlx wxt@latest init` (vanilla-ts), git init, ESLint/Prettier | `pnpm dev` открывает Chrome с пустым расширением |
| 1 | `src/core`: таблицы, detect, toLatin, toCyrillic, casing + vitest (≥ 60 кейсов, включая Щ, Ё, Ъ/Ь, регистр, смешанный текст, пунктуация) | все тесты зелёные |
| 2 | Popup: textarea → результат, выбор стандарта, кнопки Copy / Swap / Open window; подтягивание выделения с вкладки | работает на любой странице |
| 3 | Отдельное окно (`windows.create`, запоминание размера/позиции в storage) | открывается из popup и по хоткею |
| 4 | Content script: тултип при выделении (Shadow DOM, позиционирование по `getBoundingClientRect`, скрытие по клику/Escape/скроллу, debounce 150 мс, игнор выделения внутри input/textarea по настройке) | не ломает Gmail, Google Docs, GitHub, Яндекс |
| 5 | Контекстное меню, settings page, i18n (ru/en через `_locales`) | |
| 6 | Иконки 16/32/48/128, скриншоты 1280×800, описание, privacy policy | папка `store/` собрана |
| 7 | `pnpm zip` → загрузка в Dashboard → unlisted → тест на 2–3 машинах → public | расширение в магазине |

## 6. Локальная разработка и отладка

```bash
pnpm install
pnpm dev            # WXT поднимает Chrome-профиль с авто-перезагрузкой
pnpm test           # vitest
pnpm build          # .output/chrome-mv3/
pnpm zip            # .output/translitra-<version>-chrome.zip
```

Ручная загрузка: `chrome://extensions` → Developer mode → Load unpacked → `.output/chrome-mv3`.
Логи service worker: `chrome://extensions` → «Inspect views: service worker».
Чек-лист страниц: обычный сайт, SPA (GitHub), contenteditable (Gmail), iframe, PDF-вьюер
(там content script не работает — это ожидаемо), страница с CSP (тултип в Shadow DOM
не зависит от CSP страницы, inline-стили из content script ок).

## 7. Публикация в Chrome Web Store

1. **Аккаунт разработчика**: https://chrome.google.com/webstore/devconsole — Google-аккаунт,
   разовый взнос $5, подтверждение e-mail. Для публичных расширений надо указать
   контактный e-mail (виден в карточке) и пройти 2FA.
2. **Что подготовить заранее** (папка `store/`):
   - ZIP из `pnpm zip` (внутри: manifest.json в корне, без `node_modules`, без source maps).
   - Иконка 128×128 PNG (без прозрачных полей по краям больше ~16px).
   - 1–5 скриншотов 1280×800 (или 640×400), JPEG/PNG, без скруглённых углов.
   - Small promo tile 440×280 (необязательно, но без него карточку не продвигают).
   - Короткое описание (≤132 симв.) и полное описание (ru + en).
   - **Privacy policy URL** — обязателен, т.к. расширение читает выделенный текст
     (категория «website content»). Достаточно страницы на GitHub Pages / gist:
     «весь текст обрабатывается локально, ничего не передаётся и не хранится».
   - **Single purpose**: «Транслитерация текста между кириллицей и латиницей».
   - Обоснование каждого permission в одну-две строки (contextMenus — пункт меню;
     storage — настройки; activeTab+scripting — чтение выделения по клику на иконку;
     host permissions `<all_urls>` — показ подсказки при выделении на любой странице).
   - Заполнить Data usage: «не собираем данные», подписать сертификацию.
3. **Загрузка**: Add new item → ZIP → вкладки Store listing / Privacy / Distribution.
   В Distribution сначала **Unlisted** (ссылку даёшь тестерам), публичным сделать потом —
   смена видимости не требует повторного ревью кода.
4. **Ревью**: автоматически + вручную. С `<all_urls>` обычно 1–7 дней, иногда до 2–3 недель.
   Частые причины отказа: нет privacy policy, неубедительное обоснование host permissions,
   описание не совпадает с функционалом, лишние permissions. После одобрения — 30 дней
   на ручную публикацию, если выбран deferred publish.
5. **Обновления**: поднять `version` в `package.json` (WXT прокинет в manifest) →
   `pnpm zip` → Upload new package → Submit. Можно автоматизировать через
   `chrome-webstore-upload-cli` в GitHub Actions (нужны client_id/secret/refresh_token
   от Google Cloud проекта с включённым Chrome Web Store API).
6. **Лимит**: новому издателю доступно 2 опубликованных расширения — для этого проекта хватит.

## 8. Риски

- Обратный транслит неоднозначен — заявить это в UI, не обещать «точного перевода».
- `<all_urls>` удлиняет ревью — иметь готовый текст обоснования; при желании можно
  выпустить v1 без content script (только popup/окно/контекстное меню с activeTab),
  а тултип добавить в v1.1 после первой публикации.
- Тултип не должен появляться в полях ввода при наборе текста — по умолчанию включить
  игнор `input/textarea/contenteditable`, с переключателем в настройках.
